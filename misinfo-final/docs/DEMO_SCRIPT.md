```json
  "include_counter": true

```

- `"verdict": "FAKE"` + `"confidence": 0.94`
- `"risk_score": 92` + `"risk_level": "CRITICAL"`

- Point to `"cached": false` → "First time this claim was seen"

**Run the same request again:**
- `"cached": true` → "Now served from Qdrant in milliseconds — 10x faster"

## Judge Questions — Prepared Answers

**Q: How is this different from Alt News or Boom Live?**
A: Those are human-operated — 4 to 48 hours per claim. We're real-time, automated, and multilingual. We also predict virality and generate counter-narratives — not just verdicts.

**Q: Why Qdrant specifically?**
A: Three reasons: (1) multilingual embeddings mean Hindi and English versions of the same claim share vector space — one lookup covers both. (2) The hit-count payload drives our trending tracker without any extra database. (3) We reuse the same infrastructure for both misinformation claims AND segmentation class analysis — one vector DB, two use cases.

**Q: What happens when Claude API is not configured?**
A: The system falls back to pre-written counter-narrative templates in Hindi and English. Every core feature works without any paid API — Qdrant's free tier, Wikipedia, and the open-source NLI model are all we need for a full demo.

**Q: How accurate is the fact-checker?**
A: We use an ensemble of 4 sources. When Google Fact Check API has a result, accuracy is ~92% (professional fact-checkers). The NLI fallback alone is ~70%. The ensemble is always more accurate than any single source.

**Q: Can it handle WhatsApp forwards?**
A: Yes. The `/analyze/audio` endpoint transcribes voice notes via Whisper (supports Hindi and Tamil audio), then runs the full pipeline on the transcript. For text forwards, the `/analyze` endpoint handles Unicode WhatsApp text directly.
